# Definition of Ready
Le projet peut entrer en phase de conception technique lorsque les
conditions suivantes sont remplies.
## Besoin
- [x] Le problème métier est défini.
- [x] L'objectif du produit est défini.
- [x] Les utilisateurs sont identifiés.
- [x] Les besoins par rôle sont documentés.
## Périmètre
- [x] Le MVP est défini.
- [x] Les fonctionnalités hors MVP sont documentées.
- [x] Les priorités sont définies.
## Métier
- [x] Le cycle de vie d'une intervention est défini.
- [x] Les règles de changement de statut sont définies.
- [x] Les règles d'affectation sont définies.
- [x] Les règles d'archivage sont définies.
- [x] Les conflits de planification sont définis.
## Données
- [x] Les principales entités sont identifiées.
- [x] Leurs relations sont définies.
- [x] Les données collectées sont justifiées.
- [x] Les contraintes métier sont documentées.
## UX
- [x] Les principaux parcours sont définis.
- [x] L'architecture de l'information est définie.
- [x] Le parcours mobile du technicien est défini.
## Accessibilité
- [x] L'accessibilité fait partie de la Definition of Done.
- [x] Les parcours essentiels sont réalisables au clavier.
- [x] Les informations ne reposent pas uniquement sur la couleur.
- [x] Les principes de gestion des erreurs sont définis.
## Éco-conception
- [x] Les fonctionnalités sont limitées au besoin métier.
- [x] Le rendu serveur est privilégié.
- [x] JavaScript reste optionnel tant qu'un besoin ne le justifie pas.
- [x] Les données collectées sont minimisées.
- [x] Les fonctionnalités coûteuses hors MVP sont identifiées.
